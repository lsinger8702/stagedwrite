# 已有对象接入：设计边界

状态：提案，未实现、未定稿；不是 0.0.1 已有接口。

## 要解决的情形

一次 run 的 project 已成功、task 结果未知，调用方选择 close_unresolved。
原 run 保持 closed，已确认回执保留，task 继续标为 unknown。
后续工作应能引用已确认的 project，而无需重新创建它。
这与直接把原 run 改成 failed 或让 unknown 步骤自动续跑不同。

## 首批约束

- 优先支持从本库已持久化的 applied/reused 回执选择已有对象；外部任意 remoteRef 导入单独设计。
- 绑定执行器 ID/version、target、定义身份、sourceRunId/sourceStepId、remoteRef 和原输入摘要。
- 记录调用方 actor、证据引用、命令身份，保留来源链；用户声明不能自动成为库独立核验的事实。
- 接入后的已有对象不能生成 create 步骤；下游输入通过经过检查的引用取得其 remoteRef。
- 不赋予更新、删除或补偿能力；已有对象是否仍存在、是否属于目标账户由 adapter 的核验契约决定。
- 旧 run、unknown 步骤及其原请求保持原状。不能把未知步骤复制成新的 create 来绕过核对。

## 定稿前必须解决

1. 图节点如何表达 existing 身份，以及哪些字段只读；不能把 remoteRef 混入普通可编辑业务字段。
2. 计划如何显式消费已有引用；与当前 reused continuation 的语义区别是什么。
3. 如何阻止同一未知效果在新草稿被重新创建：仅换 nodeId 不构成新意图的证明。
4. 来源链被归档时如何继续验证，以及对象已删除或目标配置漂移时如何阻断。
5. 首批是否只允许接入与未知步骤无关的新工作；若要继续原 task，必须先解决其效果不确定性。

## 验收要求

project 不再创建；新下游正确引用 project；目标漂移和来源不匹配拒绝；重复接入幂等；
原 unknown 不被伪装为零效果；重启后来源、回执和身份限制仍有效。
接口命名与数据模型将在这些约束明确后确定，本轮不增加占位 API。
