# 002：复杂写入场景适配边界

状态：设计评估，未实现。2026-09-12。根据一个广告投放代码快照做静态对照；这里仅保留通用设计结论，不包含其源码、私有规则、日志或账号数据。未执行原系统测试，不代表运行验收。

## 结论

显式装配、实例作用域和启动校验方向适合复杂系统；仅注册节点字段 schema 还不足以覆盖完整写入流程。当前 0.0.1 原型和计划中的标量核心 MVP 都不能作为真实投放系统的直接替代。

## 适配矩阵

| 真实需求 | 现有/计划覆盖 | 设计处理 |
|---|---|---|
| 节点 ID、类型、关系 | M1/M2 的基本方向可表达 | 根、关系基数、共享引用由结构配置和后续规则描述 |
| 嵌套对象、数组、对象与数组整体替换 | 标量 MVP 不支持 | 必需扩展；整值支持不等于任意数组索引 OP 支持 |
| 公共字段与渠道覆盖字段同名 | 单字段空间不支持 | 预留受定义约束的命名空间，坐标包含 node/space/path |
| 显式输入、明确清空、每轮推导 | 三态原型仅覆盖前半 | 作者状态与本轮 resolved graph 分开，推导不默认为作者输入 |
| 回到未声明与恢复发布基线 | 核心 reset 只做前者 | 基线恢复用独立 restore 操作/命令；禁止更改 reset 的通用含义 |
| edit 与 preview 同解 | 当前无 preview | 共用纯 evaluateEdit，提交壳负责 CAS、版本和缓存失效 |
| 复制子树、替换共享素材、孤儿回收 | 原始图 OP 不提供业务快捷操作 | 将快捷命令展开为确定的核心 OP；回收时机与失败行为需显式契约 |
| 删除后 ID 不被重新分配 | 尚未规定 | M2 必须防身份复用；UUID 或墓碑集合，恢复原身份需独立语义 |
| 反复编辑/发布同一业务容器 | 当前发布后永久封存 | MVP 仍一次发布；长期容器采用 revision + run，后续单独设计 |
| 初始非空图/导入已有对象 | M1 只有空图 | 后续受校验的 initialGraph/import；保留来源与远端引用 |
| 预检中解析、上传素材、平台 validate-only | 同步 Rule 无法覆盖 | 只读证据、纯计算、副作用获取分开，副作用进入执行记录 |
| 检查结果、确认身份、远端漂移 | 随机句柄不足 | 结构/规则/执行计划版本与证据分别绑定；证据时间不能任意混入意图身份 |

## M2 前需要确定的通用契约

1. evaluateEdit 返回 candidate 与变化事实，不写库、不改发布基线、不自动推导；preview 和 edit 复用它。
2. 一条 OP 的内容变更与意图变更同时产生；不可先跑完整批内容、再补一遍意图。
3. 父子路径覆盖有明确定义；null、空对象、空数组、缺失、clear 分别表达。
4. 若公开一个统一 ops 数组，严格按其顺序执行，不内部改成拓扑优先。旧系统的两段数组需要显式转换和兼容规则；不能声称完全等价。
5. 普通 add 不得重用曾删除节点 ID。初始图导入、fork、restore 的身份规则分别确定。
6. 编辑可留下业务未就绪状态；不能把发布必填或业务枚举检查全部塞进编辑拒绝路径。MVP 的已填值结构检查是明确选择，不保证接受旧系统的所有编辑输入。

## 两个不能混淆的操作

- reset：清除作者对字段的声明，让解析规则重新决定；不是恢复上次发布值。
- restore：恢复到指定的可信基线版本，连同意图/关系一起恢复；不是远端回滚。未来若提供，必须拒绝不存在的基线，并处理未了结发布。

两者不由 adapter 自定义为不同含义。旧接口若把恢复叫 reset，兼容层需要显式翻译；不能直接把名字对接。

## 推荐分层

可序列化 Definition：对象结构、关系、字段空间、检查阶段元数据。
显式 Runtime binding：规则、解析器、计划器、执行器、恢复能力与稳定版本。
业务便捷命令：复制、整树创建、素材替换等，最终生成受同一核心校验的编辑请求。

检查器消费准备发布的同一份产物。上传素材等副作用不能藏在普通校验函数；预览不得触发它们。原系统里的渠道阶段数量、Go 分层与历史 sidecar 不照搬。

## 范围处理

保持 0.1.0 核心 MVP 小而可验收。上述缺口中“纯编辑计算、身份不复用、能力装配检查”进入核心设计要求；嵌套数据/命名空间/基线恢复/长期容器单独列为复杂场景扩展。

在这些扩展和迁移测试完成前，只能声称已验证基础控制流，不能声称兼容完整广告 draft。Schema 冻结不等于远端状态被冻结，注册完成也不等于业务适配完成。
