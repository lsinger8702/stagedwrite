## 1. 参考核查结论

核查依据为参考的实际输入校验、求值器和行为测试，而非仅凭注释。发现个别注释已落后于实际 reset 实现，因此以执行分支与测试为准。不将参考代码或领域结构搬入仓库。

| 项目 | 核查到的行为 | 本库处理 |
|---|---|---|
| 字段 op | set/remove/reset；set 必须有 value，另两种禁止 value | 采用；null 是合法 JSON 值，不等于缺失 value |
| 字段身份 | 在请求前图中存在，不能指向本批新建节点 | 采用 |
| scope | 必填，未知或空值拒绝 | 采用；本期仅 canonical，不开放未实现空间 |
| 重复字段坐标 | 规范化后重复整批拒绝 | 已确认采用，message/hint 必填 |
| 双通道顺序 | 拓扑先、字段后；各段按序 | 采用；不是任意交错数组 |
| remove 后改字段 | 整批失败，无版本或图变化 | 采用 |
| 节点 reset 后改字段 | 先恢复节点，再执行字段；字段 reset 仍读固定基线 | 采用；恢复出的 ref 若请求前不存在，字段修改留到下一批 |
| 节点 reset | 恢复本节点；普通子节点不自动全部复活；父节点须先存在 | 作为通用节点恢复设计依据，具体关系槽位另定 |
| 基线外节点 reset | 等价本地移除，仍受删除保护 | 采用目标；不能绕过 Run/Binding 保护 |
| 从未发布时 reset | 参考限制更严 | 保留本库已批准 initialSnapshot 基线，非照抄；create 后也能撤回声明 |
| 克隆 | 新身份、深复制；某些引用继续共享 | 采用身份隔离；不能把所有边递归克隆 |
| 孤儿回收 | 参考有按每条拓扑操作立即回收的特定关系 | 通用库不得猜关系所有权；待注册契约定义，不能无条件回收无入边节点 |
| 嵌套 | 对象祖先/后代修改按序；数组索引有额外约束 | 必须单列路径语义，不能把递归 JSON 支持等同任意数组操作 |

## 2. 字段通道目标形状

```ts
type FieldPatch = {
  ref: string;
  scope: "canonical";
  path: string; // 非空 JSON Pointer，相对于节点 fields
} & (
  | { op: "set"; value: JsonValue }
  | { op: "remove" | "reset"; value?: never }
);

type EditBatch = {
  graphPatches?: TopologyPatch[];
  patches?: FieldPatch[];
};
```

拒绝未知属性与未知 op；禁止把 node.add 等旧动作藏进 value.action。`TopologyPatch` 尚待下一节的关系语义闭合后定义，不能提前导出一个宽泛 JSON 类型冒充完整协议。

set 写作者声明与普通值；remove 写显式清空声明并删除普通值；reset 恢复批次开始时固定基线的声明和值。不存在的基线字段恢复未声明。三者均不承担远端请求效果。

## 3. 拓扑契约必须补齐的准确范围

目标沿用两类 set 坐标：`parentRef + value spec` 新建、`ref + path + value` 修改已有关系槽位。remove/reset 使用节点 ref，禁止同时传 path/value/parentRef。三类 op 均在未开始执行的本地图阶段工作；既有 Run 的图稳定约束不能放开。

参考用固定业务结构决定父子与共享关系；本库的 NodeType/EdgeType 注册目前不能完整表达这些机制。需要补充明确关系所有权，而不是按节点类型名称猜测。以下是待完成的通用化设计工作，不是已批准的新能力：

- 关系槽位由注册定义指定可接受目标类型、单值/多值、拥有/引用。字段 path 与关系 path 不得重叠。
- 拥有关系需要唯一父和无环；引用关系允许共享。是否允许引用环，必须与现有图校验契约一致，不能顺带改变。
- 删除拥有子树时，如何处理外部指入的引用：先明确阻断或保留规则，不静默删引用者。
- 克隆遍历拥有关系；子树内部引用重映射、外部引用保留或拒绝必须明确。克隆来源快照固定，不能读取途中变化状态。
- 根意图由 create spec 提供；edit 是否可增加根节点需明确定义，不能用空 parentRef 表示两种意思。
- 恢复已删除的基线身份不是创建新身份；tombstone 约束必须区别恢复和新建复用。
- 跨 Draft 的 Artifact 来源需要加载与身份/定义校验；本地 clone 和跨 Draft 复制不能凭一个裸 ref 混用。

## 5. 回执与预演

继续使用轻量编辑回执；新增 createdRefs 时必须包含来源输入位置与实际新 ref。建议位置使用批次 JSON Pointer（例如 `/graphPatches/0/value`），不是仅返回无对应关系的 ID 数组。恢复旧身份单独说明为变化，不冒充新建。

preview 与 edit 使用同一候选求值器；preview 不保存 Draft、不授予发布凭据，不允许将其临时身份用于后续请求。真实 edit 返回最终仍存在的新身份；失败不返回可持久引用的身份。准确返回类型在 M01 完整契约定稿时补齐。

## 7. 重复字段坐标的拒绝诊断（已确认）

对整批字段 patches 先解析并规范化坐标，比较 `(ref, scope, decodedPointerSegments)`，再进行任何候选变更。不以原始字符串拼接作为坐标键。不同节点不冲突；同一路径使用不同 op、相同值、重复 reset，都构成重复。父子路径重叠不等于相同坐标，仍按独立的嵌套路径规则处理。

诊断至少包括稳定 code、冲突输入位置、字段坐标、非空 message 与 hint。以下为诊断对象示例，不代表现有引擎已经返回此形状：

```json
{
  "code": "PATCH_SELF_CONFLICT",
  "path": "/patches/1",
  "relatedPaths": ["/patches/0"],
  "ref": "task1",
  "scope": "canonical",
  "fieldPath": "/title",
  "message": "patches[0] 与 patches[1] 重复修改 task1 的 canonical:/title；本批全部未应用。",
  "hint": "请为该字段保留一条表达最终意图的 OP；若确实需要两次独立编辑，请分批提交，并用第一次返回的 version 提交第二次。"
}
```

- message 说明具体发生了什么，不能只给错误码或“参数错误”。
- hint 提供调用方/LLM 可执行的调整方向，不替用户决定哪个值才是其最终意图。
- hint 不是自动生成并执行的 repairOps；候选修复仍可选。
- 同一坐标出现三次以上，应报告全部冲突位置；不同冲突组分别诊断，不只返回最后一次冲突。
- preview 与 edit 必须同样拒绝；整批零写入，不递增 version、不失效旧检查、不生成可用 createdRefs。
- 验收须覆盖 set/set、set/remove、remove/reset、相同值重复、三条重复、多个冲突组、不同 ref、父子路径；同时验证 message/hint 非空且索引真实可定位。
