# 000：项目原则与设计变更约束

**后续开发遇到与本文原则冲突，必须先与项目所有者讨论具体冲突，取得明确同意，再修改方案、代码、测试和默认行为。旧代码、评审意见和历史文档不能替代这一步。**

**2026-09-15：项目所有者已批准本轮生命周期方案并要求实施。新主线是长期 Draft、首次发布只认领一个 Run、固定基线 reset、普通 Graph 与独立意图、外部注册锁与存储。此前“同 Draft 多次 publish 独立创建”的原则已被明确替代。**

实现契约见 [018](018-draft-lifecycle-proposal.md)。**`createStagedWrite` 是唯一引擎入口。项目所有者明确要求：尚无外部使用者，不维护原型兼容；旧引擎、专属存储/示例/测试直接删除。共用的图、Schema 和诊断模块保留。**

**2026-09-16：项目所有者明确同意 [020 update 契约](020-update-contract-proposal.md)：固定图/固定远端 ID 字段更新、未决 Run 必须 resume、无写入发布持久确认、drift 冲突阻断、无远端 CAS 的首个接入限定单写方、本 Run 成功节点仍受保护。以下为批准的目标原则；运行时目前仍是首次创建阶段，update 尚未实现。**

## P1：图式工作意图

**Draft 是长期的图式工作意图容器，create 必须携带非空初始工作内容。节点和关系显式描述，单节点也是图。schema 不负责猜测本次意图。**

节点 schema 引用、节点关系、远端资源 Binding 是不同身份。一个 Draft 可管理多个节点对应的资源；不能把 Draft ID 直接当远端对象 ID。

## P2：意图、三态 OP 与固定基线

**普通 Graph 是业务值投影，fieldIntents 是字段声明的权威；两者原子维护并校验一致。set 为显式值，remove 为显式清空；null、清空与未声明不可合并。**

**reset 恢复固定基线中的字段声明，不是撤销上一个 edit。首次成功前基线是 create 的 initialSnapshot；未来 update 阶段基线是最近全量成功发布的意图。基线未声明该字段，reset 才恢复未声明。必须保留基线，不能仅删除声明或从当前值猜上版。**

本版 create 的普通字段归一为 set，包括 null；初始字段缺席表示未声明。没有 autofill 或默认值写回作者意图。多次 OP 按顺序原子应用，版本用于 CAS，不是完整编辑历史。

## P3：面向 LLM 的具体诊断

**preflight 必须返回被检查版本的完整 preview 和实际命中的问题。message 解释哪里错、为什么错；不能只给规则目录让 LLM 自己找。**

**候选值、候选附带 repairOps、多组 repairs、hint、metadata 和关联位置都是可选建议。库不自动选择修复；调用方/LLM 根据用户意图生成或选择 OP。**

**同步规则用于无 I/O 的静态检查。异步检查返回 complete 或 pending，上游重入 preflight；pending/incomplete/blocked 均不授予发布资格。库不自建任务队列。**

**每次 preflight 重新执行适用规则，不复用旧检查作为本轮发布资格。本版不增加缓存接口、缓存 key 注册或缓存存储；使用方可在规则函数内自行管理缓存、依赖参数和失效，涉及 I/O 使用异步规则。等待预算耗尽的规则仍按 pending 处理。**

preview 显式显示三态，响应格式与普通持久化 Graph 可不同；不能把 preview 当真实请求体。注册方负责 plan、真实请求映射和远端错误到图路径的映射。

**edit 返回轻量回执：draftId、version、preflightRequired 与本批 changes；不附完整 Graph、fieldIntents、初始基线或执行归属。完整存储快照用 getDraft 查询，诊断与完整当前 preview 由 preflight 返回。**

## P4：意图与执行事实分工

**Draft 保存长期身份、当前意图、固定初始基线、currentRunId 和成功产物引用；执行进度和历史请求属于 Run。currentRunId 是归属指针，不是进度、临时锁或仅供 create 使用的字段。**

**Binding 在每个节点成功时保存。缺 Binding 不证明远端不存在；未知请求必须保留在尝试记录里。published 仅表示当前意图全量成功，pending 仍可能已有部分远端资源。**

不要求 Draft 做 Git 式历史；必须保留 Run 已采用的产物、原请求和恢复证据。密钥不进入 Draft。

## P5：发布归属与续作

**一个 Draft 最多一个首次创建 Run，同时最多一个未解决 Run。Run 创建与 currentRunId 写入必须同事务，失败、超时、失锁、编辑不能清空归属。有未解决 Run 时再次 publish 只观察并提示 resume；显式指定不同 Run ID 拒绝。独立创建另一组资源用新 Draft。**

**未全部成功时继续执行用 resume，不以进程崩溃为前提。根据诊断 edit 后仍 resume 同一 Run；成功部分不重发，未知部分先用旧输入和旧请求身份查证。**

**全量成功后，新意图可在同一 Draft 认领 update Run，保留历史 Run、成功基线和 Binding。重复已采用凭据仅观察原提交；版本或 digest 不能代替归属判断。无差异发布不建执行 Run、不发远端请求，但必须原子保存采用记录与成功基线。详细分派见 020。**

## P6：互斥与恢复

**执行使用外部注册的 Draft 级租约；edit 也取同一锁。引擎管理获取、续租与条件释放，存储原子验证有效执行权。锁键不能包含本次新 Run ID 或 Draft version。乐观版本检查不替代执行锁。**

**先保存原请求/key/待确认尝试再发送；成功立即保存回执与 Binding。超时不是未生效，LLM 的重试建议也不是效果证据。未知未解决前不发新输入。**

单独两个 lock/unlock 回调不足以保证安全；Store 与 provider 要有可原子验证的协议。失锁停止推进，晚到事实只能供新合法执行者采纳。具体后端部署支持必须由实际测试证明。

## P7：本版范围与修复限制

**任一未完成 Run 内，只允许未完成节点的字段修复。该 Run 成功节点的完整意图不可变，即使 planner 忽略某字段；节点、边、步骤身份、顺序和依赖保持不变。全量成功后的新 update Run 可更新原节点，不受历史 Run 永久封锁。**

**本阶段开放固定图、固定远端 ID 的字段 update，以及受管字段的 diff/drift；新增、删除、替换资源、rollback、自动推导、action 队列仍不做。drift 冲突阻断，不静默覆盖。没有远端条件写时不能声称解决外部并发，首个接入限定单一写入方。reset 不是 rollback；unlock 不是放弃执行。**

**本版不另存 pendingPatches；edit 返回当批变化，安全修复比较 Run 已采用意图与当前意图。版本号本身没有替代字段差异，净差异也不等于完整操作历史。**
