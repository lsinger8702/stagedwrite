# 025：有限诊断修复循环

**遵循 000、019、023；2026-09-17 所有者批准。模型不得宣布发布成功，不控制 Draft/Run 身份、证书、版本或授权。只输出三态批次、问题或停止原因。**

`repairDraft` 接已有非空 Draft ID、用户目标、可选宿主确认的 Run ID、A1 tools 和模型回调。create 由宿主通过 A1 完成并登记归属；本循环不自动重建 Draft。复用三态 editBatchSchema，模型 JSON 必须在运行时校验，禁止多余字段。

每轮以检查/执行响应的 preview 和 diagnostics 作为同版本上下文，不额外读取新图拼接旧诊断。edit 成功后完整 preflight；版本冲突丢弃旧批次、重新检查后重新让模型决策。格式错误与 edit 拒绝计数独立于成功编辑后仍无进展；未知后端错误立即交宿主，不当非法 OP 重试。

passed 只有带 certificate 才可 publish；已有本轮 Run 则 resume。unknown 返回等待，下一次宿主显式以同 Run 进入才查证，不自动忙轮询。pending/incomplete 返回等待，不授予发布资格。blocked 有诊断才交模型，缺少诊断返回需人工处理。

每次入口有轮数、工具调用次数和模型时间预算；取消/超时不再启动新操作。在途引擎写入必须等其结果，不用 Promise.race 把写入遗留后台，也不声称取消能撤回远端效果。模型调用可取消，迟到输出不会执行。工具逐个 await；跨入口并发仍由引擎租约/CAS 防护。历史记录只作解释，不能作为重新派发写入的脚本。

Messages 样例使用单个提交决策的工具，模型不自由选择七个执行工具。每轮独立请求含有限历史，不需要第二套长期会话存储。缺值返回问题，宿主补充目标后重新进入；不自行实现审批、长期队列、自动填充或意图审计平台。
