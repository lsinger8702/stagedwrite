# 0.1.0 核心 MVP

状态：计划。当前 package.json 的 0.0.1 是探索原型，不代表本页已实现。

## 用户和完整场景

开发者在自己的程序中注册结构、规则和模拟 Adapter。使用者创建 Campaign → AdSet 对象图，通过 OP 填充，预检发现缺项并给出修复建议；使用者明确应用后发布。模拟远端生效但本地未收到结果时，执行器停止，重启后先查证再恢复。

广告对象仅作为通用图示例；不包含平台私有规则或生产集成。

## 必须交付

| 能力 | 验收条件 |
|---|---|
| 独立定义、启动装配并冻结 | 未定义端点类型的关系被拒绝；旧草稿继续使用原版本 |
| 对象图 | 节点、边有稳定 ID；单节点也是合法草稿 |
| OP 与版本检查 | stale version 被拒绝；无效批次不留部分修改 |
| 结构与完整性分离 | 缺必填字段允许保存，错误字段类型不允许保存 |
| 预检与修复 | 诊断含 OP 或明确阻塞原因；不自动替用户改变意图 |
| 发布计划固定 | 修改使旧检查结果失效；发布中不能篡改原计划 |
| SQLite 持久化 | 草稿、版本、计划、执行状态和事件在重启后仍可读取 |
| 顺序执行与部分成功 | 保留已成功步骤和远端引用；失败后不丢失效果信息 |
| UNKNOWN 与恢复 | 生效后断线先查证；不明确则停住；成功步骤不重发 |
| 可运行仓库 | 文档、示例、自动测试；干净环境可按 README 运行 |

## 明确边界

单执行器进程、可信代码注册。节点字段先限定标量；关系由显式边表示。MVP 不包含嵌套任意 JSON、数组编辑、动态插件、在线 schema 注册、自动合并、完整规则 DSL、自动补偿、多进程 fencing、租户权限、Web 界面、Stripe 和 MCP。

SQLite 解决本地持久性，不使外部写入成为原子事务。Adapter 必须解释查证依据；查无对象不自动等于未执行。不声称 exactly-once 或预检完备。

## 发布前的故障验收

- [ ] 同一批创建节点、设置字段、建立关系成功，版本只增加一次。
- [ ] 批次含非法关系时，图和版本均不变。
- [ ] 改草稿或切换执行相关定义后拒绝过期计划，不能静默重新解释。
- [ ] 重复 publish 返回已有 run，不重复派发。
- [ ] 在派发前后、本地结果落库前后终止执行器，重启不丢失可审计状态。
- [ ] 假远端已生效但本地未记录，恢复查证后跳过，不重复效果。
- [ ] 查证结果仍不明时，后续步骤没有被调用。
- [ ] 原请求被权威证明终止且无效果后，允许使用原键重试。
- [ ] 所有声明明确区分本地模拟与真实远端保证。

## 适配声明（2026-09-12）

当前 MVP 是基础控制流验证，不是完整广告草稿兼容层。嵌套对象/数组、覆盖空间、发布基线恢复、持续编辑发布尚不在此范围。参见 [适配矩阵](design/002-complex-draft-fit.md)。

核心增加验收要求：编辑/预览共用纯候选计算；普通新增不复用删除节点 ID；完整执行模式缺必要运行能力时装配失败。M1 只装结构时明确不可发布。
